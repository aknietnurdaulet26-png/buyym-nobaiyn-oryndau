# Нобай LAB — открытый урок Гүлмиры

Тот же проект: https://aknietnurdaulet26-png.github.io/buyym-nobaiyn-oryndau/

Обновление v2: казахский/русский интерфейс, исходные 66 вопросов с русскими переводами, до 30 учеников, 15 вопросов на ученика, QR-приглашения, два режима, восстановление сессий и CSV.

## Статус подключения — прочитать перед уроком

В исходном репозитории НЕ было Firebase или серверной базы: использовался PeerJS. Он сохранён как транспорт по умолчанию. Прямое WebRTC-соединение ранее не проходило сетевую проверку в среде разработки. Обновление интерфейса само по себе НЕ устраняет сетевые ограничения NAT/брандмауэра. Работоспособность 30 физических телефонов пока не подтверждена.

Добавлен отдельный транспорт Firebase Realtime Database, но он НЕ АКТИВИРОВАН: владелец ещё не предоставил публичную web-конфигурацию проекта. Его код и правила также требуют проверки с реальным проектом или эмулятором. Для урока в сети, блокирующей PeerJS, сначала настройте Firebase по разделу ниже, затем проведите тест устройств. Не представляйте модульную симуляцию как пройденный сетевой нагрузочный тест.

## Возможности

- Казахский по умолчанию. Личный язык сохраняется на устройстве, переключение не меняет ответы и баллы.
- Имя учителя: «Мұғалім: Гүлмира» / «Учитель: Гулмира».
- QR генерируется локально, без API, содержит текущий URL и `?room=123456`. Увеличение, полноэкранный режим при поддержке браузером, копирование и выделяемая ссылка.
- Максимум 30 участников. Один идентификатор браузера не создаёт повторного участника после обновления. Для нескольких учеников на одном компьютере нужны разные профили браузера.
- На одном шаге 30 уникальных вопросов; у одного ученика 15 вопросов без повторов, по 5 каждого из трёх уровней. Ученики с номерами 23–30 начинают с другого уровня, поэтому сложность одновременных вопросов может различаться. Все получают одинаковое количество заданий каждого уровня.
- «Раунды под управлением учителя»: 30/45/60/90 секунд, ручное завершение, следующий раунд. Значение по умолчанию 45 секунд.
- «Каждый в своём темпе»: учитель запускает всех одновременно, ученики переходят после сохранения ответа. Общего таймера нет. Учитель может завершить досрочно.
- 100 баллов за верный ответ, максимум 1500. Скорость не влияет на баллы. Равные баллы дают одинаковое место.
- Общий рейтинг, присутствие, прогресс, просмотр ответов ученика по нажатию на имя, CSV с отдельными баллами по каждому вопросу.
- Неподтверждённый ответ сохраняется на устройстве и повторно отправляется при восстановлении связи. В режиме раундов ответ, доставленный после истечения времени, отклоняется. Уже подтверждённые баллы не теряются при переподключении.

## Запуск урока

1. Учитель открывает сайт, выбирает язык и «Создать комнату».
2. Показывает QR на доске. На опубликованном сайте ссылка ведёт на GitHub Pages; QR из локального предпросмотра предназначен только для локальной проверки.
3. Ученики сканируют QR или вводят шестизначный код, пишут имя и присоединяются. При совпадении имён добавляют инициал.
4. Учитель выбирает режим до начала игры. При желании увеличивает QR или включает полный экран.
5. Убедитесь, что все нужные ученики отображаются онлайн, затем нажмите «Начать викторину».
6. После игры экспортируйте CSV. «Новая комната» запрашивает подтверждение и создаёт новый код/QR.

## Сохранение и восстановление

PeerJS передаёт данные по сети; localStorage НЕ используется как замена сетевой синхронизации. Копия состояния учителя хранится в его браузере для восстановления; идентификатор ученика и неподтверждённый ответ — в браузере ученика. Учитель является авторитетом подсчёта баллов и сохраняет состояние до отправки подтверждения. Повторный ответ на тот же вопрос не начисляет баллы повторно.

После перезагрузки учитель нажимает «Восстановить комнату». Пока учитель закрыт, игра не может подтверждать новые ответы. Если код ещё занят старой вкладкой, закройте её и повторите восстановление. Ученик нажимает «Вернуться в игру» / «Подключиться снова». Автоматические попытки переподключения ограничены, чтобы не создавать бесконечную нагрузку.

Очистка хранилища, приватный режим с удалением данных или смена браузера могут потерять локальную личность/снимок. Хранится последняя комната; перед созданием следующей сохраните CSV. Старые ключи v1 не удаляются, но живые комнаты v1 и v2 несовместимы: завершите старый урок до обновления.

## Подключение Firebase (не включено автоматически)

1. Создайте/выберите Firebase-проект и веб-приложение. Получите **публичный** `firebaseConfig` с `apiKey`, `projectId`, `appId`, `authDomain`, `databaseURL`.
2. Включите Authentication → Anonymous. При необходимости добавьте домен `aknietnurdaulet26-png.github.io` в разрешённые домены.
3. Создайте Realtime Database. Не открывайте всю базу правилами `true`.
4. Примените правила из `firebase.rules.json`. Если база уже используется другим приложением, объедините только узел `nobaiV2` с существующими правилами, не удаляя остальные узлы. Широкие разрешения родительских правил могут отменять ограничения вложенных правил.
5. В `config.js` задайте `transport: 'firebase'` и настоящий объект `firebaseConfig` вместо `null`. Никогда не публикуйте private_key или сервисный аккаунт.
6. Commit в main → дождитесь GitHub Pages → обновите страницу учителя и учеников.
7. Проверьте создание комнаты, ответ, повтор ответа, запрет записи в чужой канал, восстановление и 30 подключений.

Структура базы: `nobaiV2/{code}/meta/owner`, `meta/online`, `snapshot`, `clients/{authUid}/{instance,online,up,down}`. Учитель владеет комнатой и снимком. Ученик может писать только свой входящий канал и признаки соединения, читать только свой канал; данные рейтинга доставляет учитель. `up` содержит последний пакет, неподтверждённый ответ повторяется; `down` содержит последнее состояние. Записи учителя сериализованы. Firebase сохраняет снимок комнаты дополнительно на сервере, но обработчик ответов всё ещё работает во вкладке учителя.

При включённом Firebase используется JS SDK 11.10.0 с gstatic. Бесплатность зависит от квот вашего Firebase-проекта; платные тарифы и сервисы автоматически не подключаются.

## Проверки

`node tests.cjs` — модульная симуляция 30 участников в двух режимах: 900 ответов и 900 повторов, восстановление снимка, отсутствие дублей, лимит 30, закрытые и просроченные ответы, совпадение правильных позиций на двух языках, равные места и CSV.

Это симуляция в одном процессе Node.js без WebRTC/Firebase. Подробный список фактических и ручных проверок: [TESTING.md](TESTING.md).

## Файлы

- `index.html`, `style.css` — обновлённая адаптивная мастерская, SVG эскиз, инструменты, панели, QR и диалоги.
- `main.js` — интерфейс и жизненный цикл комнаты/ученика, восстановление, CSV.
- `core.js` — распределение и единственный обработчик ответов с защитой от повторов.
- `questions.js` — исходный казахский банк, сохранён без изменений.
- `questions-ru.js`, `i18n.js` — переводы банка и интерфейса.
- `transport.js`, `config.js`, `firebase.rules.json` — PeerJS и опциональный Firebase.
- `vendor/` — локальные копии PeerJS и QR-библиотеки, без обязательного внешнего CDN для основной страницы.
- `tests.cjs`, `TESTING.md` — проверки и ограничения.

## Публикация и ограничения

GitHub Pages: `main` → `/(root)`, `.nojekyll` сохраняется. Секреты не добавлены. Это учебная викторина, не защищённая экзаменационная система: банк и верные ответы доступны в исходниках. Используйте имена/псевдонимы без лишних персональных данных. Прямое соединение зависит от публичного PeerServer и доступности WebRTC; отдельного TURN-сервера нет. Предварительная проверка на школьной сети обязательна.
